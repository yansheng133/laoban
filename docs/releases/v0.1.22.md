## 從 0.1.21 升級

- **重新套用 Rancher 角色**：`kubectl --context local apply -f https://raw.githubusercontent.com/yansheng133/laoban/v0.1.22/deploy/rancher/roletemplate.yaml`。laoban user／viewer 多了唯讀的 Deployment 權限。
- **NetworkPolicy 預設開啟**（`apps.networkPolicy: true`）。叢集的 CNI 要能執行 NetworkPolicy（RKE2 的 Canal、Calico、Cilium 都可以）。產生的應用如果原本會連叢集裡別的服務，升級後會連不到；要維持舊行為就設 `apps.networkPolicy: false`。
- 後端啟動時會檢查每個應用的 `ingress.yaml`、`networkpolicy.yaml`，跟設定不同就用一個 commit 補齊、改寫或刪除。升級後第一次啟動通常會有這樣一個 commit。

## 新功能

- `apps.ingressAnnotations`：替每個應用的 Ingress 加 annotation，例如 Traefik 的 middleware 或 ingress-nginx 的 `auth-url`，讓應用的網址需要登入。值會寫進放應用的 repo，不要放秘密。
- `apps.networkPolicy`：每個應用兩條 NetworkPolicy。API 只接受自己網頁的連線；網頁和 API 都只能連自己的 API 和 DNS，產生的程式連不到叢集裡的其他服務。
- 後端啟動時，讓每個應用的 Ingress 與 NetworkPolicy 檔案對齊目前的設定：設定前就有的應用會補上、改了網址會更新、拿掉 `apps.url` 會刪除。

## 修正

- 只有 laoban user 角色的人部署後一直等到 10 分鐘逾時（B26）：角色沒有讀取 Deployment 的權限。
- 應用從 repo 刪掉後，它最後一輪意見收斂的紀錄（`lbround`）一直留著（N36／N42）。後端啟動時與之後每 10 分鐘，刪除已結束、已歸檔的這類紀錄。
- AI 第一次發布常常失敗（N46）：計畫把 API 模組取名 `server.py`，產生程式時就用了這個檔名。現在要求模組用功能命名，API 程式一律叫 `handler.py`；萬一只回了一個名稱不同的 Python 檔，也當成 `handler.py` 接受（仍要有 `handle()`）。
- 部署進度先顯示舊版本的「1 / 1 ready」再變成「0 / 1」（N39）：Fleet 還沒接手新 commit 時，改顯示「等待 Fleet 接手」。
- 舊 Pod 停止的幾分鐘裡進度一直是「0 / 1 ready」（N40）：Fleet 還沒回報完成時也檢查 Deployment，新版本跑起來就算完成。
- 版本清單與意見裡顯示使用者 ID（N41）：改顯示 Rancher 的顯示名稱（看得到該使用者時）。
- 唯讀的人看到可以按、按下去是空白的「Comments (0)」（N35）：沒有留言、也不能留言時不顯示。
