## 修正

- 範圍只選「網頁」的意見收斂：計畫的 API 端點沒變時，API 的模組一律沿用目前的版本，範圍不會擴大，只有網頁的分工 AI 會寫程式。
  - 原因：較早建立的應用，計畫裡的模組是用檔名命名（例如 `note_api.py`）；AI 依現在的規則把它改寫成依功能命名，光是改名就被判定成 API 有改，結果重寫了沒人要改的 API。
  - API 真的需要改時（新增或改變端點），範圍照樣擴大到 API。
- 修改計畫時，AI 會原樣保留不受影響的模組名稱與用途，3D 圖與版本比較不再出現無意義的改名。

Fix: a round of opinions scoped to the web part no longer widens to the API just because the AI reworded the API modules (apps made earlier named modules after files, such as `note_api.py`). When the plan keeps the API's endpoints, the API modules stay as they are and only the web subagent writes code; a real API change still widens the round. Change plans also keep the names and purposes of unaffected modules. laoban is a community project, not supported by SUSE.
