## 從 0.1.24 升級

照 [快速上手](https://github.com/yansheng133/laoban/blob/main/docs/quickstart.md) 的「升級」一節升級 extension 與兩個 chart。沒有需要額外處理的設定；advisor 預設關閉。

## 新功能：請教更強的模型（advisor）

- 新設定 chart 的 `ai.advisorModel`（環境變數 `LAOBAN_AI_ADVISOR_MODEL`），預設空白。設定後（例如模型用 `claude-sonnet-5-5`、advisor 用 `claude-opus-5-5`），產生計畫、每個分工 AI、修正那一次，都會先請教 advisor 一次再寫。
- 只能搭配 Anthropic API；設了 `ai.baseUrl`（本機模型）時 chart 會拒絕。
- advisor 用的 token 計入每月上限，依 advisor 模型的價格計費；分工 AI 的卡片顯示「請教了哪個模型、用了多少 token」，總覽的設定區列出 advisor。
- 實測（三分頁早餐店，各一次）：有 advisor 128 秒、約 68,000 token；沒有 92 秒、約 25,000 token；兩個應用都能用，看不出品質差異。所以預設關閉。

## 修正（依獨立審查）

- **約定比對看 HTTP 方法**：計畫同一路徑有 GET 與 POST、API 只寫了一個時會抓到；網頁用計畫沒有的方法呼叫時也會抓到。`api/orders/${id}/items` 這類參數後面還有路徑的呼叫、執行時才組好的路徑，不再誤判成計畫外的呼叫；`"^/menu$"` 這種寫法算有處理。
- **修正那一輪每一邊各自採用**：兩邊都要修、其中一邊失敗時，成功的那份不再被丟掉。「修正過一次」只標在真的採用的那一邊。
- **請求與回應範例必須是 JSON**：不是 JSON 的文字一律清空，避免夾帶給 AI 的指示。確認計畫的畫面（新應用與意見收斂）多了可展開的「API 約定」，列出每個端點的請求與回應範例。
- **舊應用的「只改網頁」**：舊計畫沒有範例、新計畫補上範例，不算 API 改變，只改網頁的輪次一樣只重寫網頁。
- **advisor 記帳**：請教到一半中斷，或一直沒完成時，已經用掉的 token 照樣計入上限，並回報「AI 沒能完成回答」，不再誤報成格式錯誤。
- 繁中介面統一用「分工 AI」。

Optional advisor (`ai.advisorModel`, off by default): every AI call consults a more capable model once (Anthropic API only); its tokens count against the cap and show on the subagent cards. Fixes from an independent review: the contract check compares HTTP methods and handles values mid-path and run-time suffixes; each part's fix is kept on its own and "fixed once" only marks a fix that was used; request/response examples must be JSON and are shown as an "API contract" where plans are confirmed; examples filled into old plans no longer count as an API change; interrupted advisor turns are counted and reported as unfinished. laoban is a community project, not supported by SUSE.
