讓 laoban 產生的應用改用自己的網址開啟，不再跟 Rancher 同網址（B25，嚴重）。

laoban 是社群開源專案，不在 SUSE 的支援範圍內。安全相關的注意事項與回報方式見 [SECURITY.md](https://github.com/yansheng133/laoban/blob/main/SECURITY.md)。

## 從 0.1.20 升級

- **強烈建議設定新的 `apps.url`**，例如 `https://{app}.apps.example.com/`（`{app}` 會換成應用名稱）。需要一個指到叢集 ingress controller 的萬用 DNS 紀錄；要用 https 的話，在應用的 namespace 放一張萬用憑證並設定 `apps.tlsSecretName`；ingress class 不是預設的話，設定 `apps.ingressClassName`。做法見 [快速上手](https://github.com/yansheng133/laoban/blob/main/docs/quickstart.md) 第 4 節。
- 設定前就有的應用，下次修改（包括調整 3D 版面）時才會加上 Ingress；在那之前，「打開應用」會連到還沒有 Ingress 的網址。
- 不設定也能升級：應用維持經 Rancher 代理開啟，但每個「打開應用」旁邊都會顯示警告。

## 修正

- **應用跟 Rancher 同網址（B25）。** 之前應用經 Rancher 代理開啟，誰打開應用，應用頁面裡的程式就帶著那個人的 Rancher 登入，能讀取 Rancher API 和防偽造請求用的 cookie；管理者打開時就是管理者權限。設定 `apps.url` 後，每個應用都有自己的 Ingress 和網址，瀏覽器不會把 Rancher 的登入交給它。實測同一個應用：經代理開啟時讀得到 `CSRF` cookie，`/v3`、`/v1` 都回 200；改用自己的網址後讀不到 cookie，兩個請求都被瀏覽器擋下。
- 只有 laoban user 角色的人，設定 `apps.url` 後也能打開應用（之前缺 `services/proxy` 權限，回 403）。

## 注意

- 改用自己網址的應用不再經過 Rancher 的權限檢查，連得到那個網址的人都能打開。請用網路或 ingress controller 的驗證機制限制誰連得到。

---

Generated apps can now open on their own address instead of Rancher's (B25, severe). Set the new chart value `apps.url` (for example `https://{app}.apps.example.com/`): each app gets an Ingress, and the browser no longer gives the app the viewer's Rancher login. Without it, apps still open through the Rancher proxy, and the page warns next to every such link. Apps made before the setting get their Ingress with their next change. Apps on their own address are not behind Rancher's permission check; limit who can reach them. laoban is a community project, not supported by SUSE.
